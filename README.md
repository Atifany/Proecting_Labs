# Лабораторная работа №1

В ADR файле 

Компонентная диаграмма модуля аналитики включает ключевые сервисы в следующем алгоритмичном порядке:
1) WEB-приложение c модулем сбора событий ассинхронно отправляет собранную статистику с сайта в rabbitMQ.
2) RabbitMQ пересылает сообщения в агрегатор событий, который подготавливает данные к записи в базу данных и записывает их.
3) ClickHouse хранит аналитические данные.
4) API аналитики по необходимости берет данные из ClickHouse и формирует отчёты.
5) Дашборд показывает удобный отчет с возможностью загрузки для аналитиков (целевой пользователь модуля аналитики)
![alt text](diagram_analitics_module.png)

Ключевые архитектурные характеристики для модуля аналитки:
1. Отсутствие циклических зависимостей
Правило: зависимости между программными компонентами не должны образовывать циклы.
Пример нарушения: API событий зависит от обработчика, а обработчик — от API событий.
Критерий прохождения: обнаружено 0 циклов.
В проекте приложен файл с псевдокодом на java CycleDependancyTest.java, иллюстрирующий работу данной проверки.

2. Соблюдение границ компонентов
Правило: обработчику запрещено напрямую зависеть от Web-приложения, а API событий — от обработчика и модуля доступа к ClickHouse.
События должны передаваться через RabbitMQ, а не прямым вызовом обработчика.
Критерий прохождения: обнаружено 0 запрещённых зависимостей.
Для обеих проверок анализирируются зависимости в коде, а не направление стрелок передачи данных на диаграмме.
В проекте приложен файл с псевдокодом на java ComponentBoundariesTest.java, иллюстрирующий работу данной проверки.
